## The Problem: Context Memory Degradation (CMD)

Anyone who has had a long conversation with an AI assistant knows what happens: the model starts to "forget" things said earlier, contradicts itself, loses the thread. Start a new session and it remembers nothing at all.

This happens because modern language models use **attention mechanisms** — every token attends to every other token at a cost that scales quadratically (O(n²)) with context length. Older information gets diluted. When the session ends, everything is gone.

The standard workaround is manual context management: handoff documents, system prompts, periodic summaries. It works — but it's a patch, not a solution. And it puts the burden of memory entirely on the human.

**The deeper question: how does the brain solve this problem?**

It doesn't rely on one system holding everything. It distributes memory across specialized regions, each handling a different type. It consolidates during sleep. It forgets selectively — pruning noise, strengthening important connections. It learns continuously from experience.

What if an AI system could do the same?

## The CSDF Architecture

**CSDF (Cognitive Self-Feedback Data Framework)** is a proposed multi-agent architecture where:

1. Memory is distributed across a tiered knowledge graph (not held in a single context window)
2. Specialist models self-select their sub-tasks from a shared prompt broadcast — no central director
3. A coordinator model checks coverage and resolves gaps or overlaps between specialists
4. Each specialist's output is evaluated against the expectations of the model it feeds into — not just against independent ground truth
5. Error localization is structural: sub-task ownership makes failure traceable to a specific model
6. New knowledge generated by the system feeds back into the database automatically
7. Collaborating models achieve coherence through joint fine-tuning on shared interaction data
8. The system generates its own training targets from operation — they emerge, they are not predefined

### Core Insight

The context window is not memory. It is **working memory** — analogous to the prefrontal cortex. Short-term, high-bandwidth, cleared after use. Long-term memory belongs in an external system, retrieved selectively, just as the hippocampus loads relevant memories into conscious attention when needed.

## The Knowledge Hierarchy

Rather than treating all stored information equally, CSDF proposes explicit abstraction tiers:

| Tier | Content | Storage | Access |
|------|---------|---------|--------|
| **Law / Principle** | Broadly applicable generalizations | HOT — always in context | Every session |
| **Theory** | Patterns that explain multiple data points | WARM — retrieved by topic | When relevant |
| **Data** | Specific facts, events, observations | COLD — retrieved on demand | When specifically needed |
| **Noise** | Low-signal information below threshold | PRUNED — discarded | Never |

This mirrors the progression from raw experience to crystallized knowledge in human learning — and in the history of science itself (observation → hypothesis → theory → law).

**Access frequency determines storage tier.** What is used often rises. What is rarely needed sinks. What never surfaces is forgotten — selectively, not blindly. This is synaptic pruning applied to knowledge storage.

## The Coherence Problem and Its Solution

In a multi-model system, a critical problem emerges: how do specialist models stay aligned with each other? If the coding model and the reasoning model develop contradictory beliefs, the system becomes incoherent.

### The Insight: Coherence Through Bidirectional Expectation Signals

The brain does not have a coherence manager. Coherence emerges from **co-activation** and **retrograde signaling**: when neuron A fires to neuron B, B fires sub-action potentials back to every neuron connected to it — changing their receptor density, modifying how sensitive they are to future inputs. A learns not just from its own output, but from what B expected to receive.

CSDF applies this principle **at the model weight level** and **between models**:

> *"Models that train together, align together — and train against each other's expectations."*

The key mechanism: each specialist's training target is not just "produce correct output" — it is "produce output that the downstream model can use effectively." The performance of the receiving model flows back as a training signal to the producing model.

This is analogous to **Spike-Timing Dependent Plasticity (STDP)** at the inter-model scale: the relationship between A's output and B's performance determines whether A's connection to B strengthens or weakens.

### How Coherence Emerges — Cold Start to Trained System

**Iteration 1 (cold start):**
- All specialists train on independent ground truth
- No predefined expected values between models are needed
- System runs, sub-task outputs are recorded alongside final output quality

**Iteration 2 onward:**
- Performance gaps become the training signal
- If B performed poorly given A's output: the gap between A's actual output and "what would have made B perform better" becomes A's new training target
- A now optimizes not just for correctness in isolation — but for how well its output serves B
- Expected values between models are not predefined. They emerge from operation.

**The training dataset structure:**

```
Each training example contains:
  - User prompt (full)
  - Sub-task declaration per specialist (who claimed what)
  - Sub-task output per specialist
  - Dependency map (which specialist's output fed which)
  - Expectation gap (what downstream model needed vs. what it received)
  - Final output + quality evaluation
  - Failure localization record (if applicable)
```

The dataset encodes not just what happened, but the relational structure of how it happened — which model was responsible for which piece, and how each piece affected what came next.

### Error Localization — No Black Box

A critical property of CSDF's architecture: **failure is always traceable.**

Because each specialist declares ownership of a specific sub-task before executing it, the ownership record is part of every interaction log. When the final output fails:

```
1. Inspect sub-task outputs against sub-task ownership records
2. Find which sub-task produced inadequate output
3. That sub-task's declared owner = the failing model
4. If multiple specialists touched related sub-tasks → narrow to a group
5. Subsequent iterations narrow further

If all sub-task outputs look correct but final output fails:
   → Error is in the main model (synthesis failure, not specialist failure)
   → Upstream models are not the problem

Training signal targets the localized model specifically — not the whole system
```

This is made possible because specialists read the **full prompt** and self-select their sub-tasks. Unlike a router-directed system where misrouting can confuse error localization, self-selection with declared ownership means the responsibility chain is always known.

### The Nightly Replay Pass

Inspired by hippocampal consolidation during sleep, CSDF includes an asynchronous nightly pass that resolves incoherence before it compounds:

```
While system is idle:
  → Retrieve flagged interactions from the day
  → Re-run through specialist chain
  → Inspect sub-task outputs against ownership records
  → Identify divergence point: where did the chain fail?
  → Detect cross-model contradictions
    (specialist A implied X, specialist B implied ¬X)
  → Generate targeted reconciliation training examples
    for the specific failing model(s)
  → Add to fine-tuning batch
  → Update knowledge tier assignments as needed
```

This is not just learning from what happened. It is **actively correcting failures before they become entrenched in weights** — the same function hippocampal replay serves in biological memory consolidation.

## The Self-Feedback Data Loop

CSDF's name comes from its central mechanism: **the system's own operation generates the data that improves it — including the training targets.**

```
Operation
  → Sub-task outputs recorded with ownership
  → Final output evaluated
  → Failure localized if needed
  → Expectation gaps computed (what downstream needed vs. received)
  → Training candidates marked
  → Nightly: reconciliation + fine-tuning
  → Better models → better sub-task outputs → better expectations
  → Repeat
```

This is a **data flywheel** — but with two properties that distinguish it from existing self-evolving systems:

1. Applied to a **multi-agent system**, not a single model — the flywheel improves alignment between agents, not just individual capability
2. **Training targets emerge from operation** — the expected outputs are not predefined by humans, they are generated by the system discovering what each model needs from the others

## Continual Learning and Catastrophic Forgetting
CSDF's self-feedback loop implies the system learns continuously from operation. This raises a well-known problem in machine learning: **catastrophic forgetting** — when a model trains on new data, it risks overwriting weights that encoded previously learned knowledge.
CSDF addresses this partially through architecture, and acknowledges it partially as an open problem.
**What the architecture handles:**
The tiered knowledge database is the primary memory layer — not model weights. Laws, theories, and data live in external storage, retrieved selectively. This means most of what the system "knows" is not stored in weights at all. Catastrophic forgetting in weights therefore affects procedural knowledge (how models behave) more than factual knowledge (what the system remembers). The external DB is not subject to forgetting.
For weight-level updates, CSDF uses **LoRA (Low-Rank Adaptation)** — training only small adapter matrices while keeping the base model frozen. This significantly reduces the risk of overwriting prior knowledge, since the base model's weights are never touched.
The nightly replay pass further mitigates forgetting by mixing new training examples with replays of important prior interactions — the same mechanism the brain uses during sleep consolidation to prevent new learning from erasing old memories.
**What remains an open problem:**
True continual learning at weight level — where a model learns seamlessly across an open-ended stream of tasks without any forgetting — is not solved by CSDF or by the field generally. CSDF's approach (external memory + LoRA + replay) gets most of the practical way there, but does not claim to solve the underlying theoretical problem.
Whether the bidirectional expectation signal mechanism interacts with catastrophic forgetting in unexpected ways — positively or negatively — is an empirical question that requires implementation to answer.

## Why Specialist Self-Selection Instead of Router Direction

A conventional multi-agent design has a router model that reads the prompt and assigns sub-tasks to specialists. CSDF inverts this.

**The problem with router-as-director:**
- Router becomes a single point of failure — misrouting looks like specialist failure
- Router must understand the full task space to assign correctly — that is a large knowledge burden for a small model
- Error localization is confused: did the specialist fail, or did the router give it the wrong input?

**CSDF's approach — broadcast and self-select:**
- Full prompt is broadcast to all specialists simultaneously
- Each specialist reads the full prompt and declares: "I am handling sub-task X"
- A coordinator model (small, fast) checks coverage: are all necessary sub-tasks claimed? Any claimed twice?
- Gaps are filled; overlaps are resolved by specialization priority or confidence

**The advantage this creates:**
- Each specialist has full context when producing its output — it knows what the other sub-tasks are, even if it is not handling them
- A can anticipate what B needs because both read the same prompt
- This is a natural form of the inter-model expectation signal — emerging from shared context before any training, not requiring explicit injection

This mirrors how the brain actually works: the thalamus broadcasts signals, and each cortical region responds to the features it is specialized for — not because it was directed to, but because it developed sensitivity to those features through experience.

## Relationship to Existing Work

CSDF is not built from nothing. It draws on and extends:

| Existing work | What CSDF borrows | What CSDF adds |
|---|---|---|
| **HeLa-Mem** (2025) | Hebbian learning for memory graphs | Applies Hebbian at weight level, not graph level |
| **Kairos / NeurIPS 2025** | Validation-gated Hebbian for KGs | Joint model fine-tuning for emergent weight-level coherence |
| **MemOS** (2025) | Tiered memory types, LoRA modules | Explicit knowledge abstraction hierarchy + flywheel |
| **GraphRAG** | Graph-structured retrieval | Co-activation as coherence mechanism |
| **Process supervision** | Evaluating intermediate steps | Evaluating steps relationally — against downstream expectations, not independent ground truth |
| **Self-evolving data flywheel** | Operation generates training data | Applied to multi-agent coherence; training targets themselves emerge from operation |
| **Semi-independent policies** (2023) | Shared representation for heterogeneous agents | Extended to LLM fine-tuning domain with bidirectional expectation signals |

**The gap CSDF addresses:**

Existing process supervision evaluates intermediate outputs against **independent ground truth** — each step is judged on its own merits. CSDF evaluates each step **relationally** — A's output quality is partly defined by how well it enables B. The training signal is bidirectional: B's performance flows back to inform A's training target.

No existing system combines:
- Hebbian co-activation at the model weight level
- Bidirectional inter-model expectation signals as the training signal
- Sub-task ownership for structural error localization
- Training targets that emerge from operation rather than predefinition

as an explicit architectural principle for multi-agent coherence.

This bidirectional expectation flow is analogous to retrograde signaling in biological neural circuits — a mechanism explored formally in predictive coding frameworks.

## What CSDF Does Not Claim

- This is a **conceptual proposal**, not an implemented system
- CSDF does not claim to produce consciousness or sentience
- Whether this architecture produces genuine cognitive ability is an **open empirical question** — and an interesting one
- The frozen weights problem means this is not true continuous learning in the biological sense — but external memory and iterative fine-tuning get most of the way there in practice
- The cold start requires standard supervised training — the novel mechanisms emerge from iteration 2 onward
